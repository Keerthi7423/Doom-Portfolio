PHASE 2: SENIOR ENGINEERING MOCK INTERVIEW (10 QUESTIONS)
--------------------------------------------------------------------------------
You must answer these verbally/in text like a senior engineer:

Q1: "As a frontend developer, you used to store JWTs in localStorage. 
     Why did we switch to httpOnly cookies on the backend?"
A1: Storing JWTs in localStorage exposes them to Cross-Site Scripting (XSS). 
    Any third-party script, npm package, or injected `<script>` tag can run 
    `localStorage.getItem('token')` and exfiltrate it. With `httpOnly: true`, 
    the browser automatically attaches the cookie to requests, but JavaScript 
    has zero access (`document.cookie` returns empty).

Q2: "What is the difference between SHA-256 and Bcrypt cost factor 12?"
A2: SHA-256 is a general-purpose cryptographic hash designed for high-speed 
    throughput. A modern GPU can compute billions of SHA-256 hashes per second, 
    making dictionary attacks against stolen databases trivial. Bcrypt uses the 
    Eksblowfish algorithm and is intentionally slow. Work factor 12 runs 4,096 
    iterations, taking ~300ms per attempt. This throttles offline brute-force attacks.

Q3: "Why did we decouple app.js and server.js?"
A3: Separation of concerns. `app.js` configures Express middleware, security 
    headers, and route handlers without binding to a network port. This allows 
    testing libraries like Supertest to import `app.js` and execute in-memory 
    HTTP integration tests without port collisions (`EADDRINUSE`). `server.js` 
    handles infrastructure: MongoDB connection and OS signal listeners.

Q4: "Why did userSchema.pre('save', async function(next)) fail with 
     'next is not a function' in Mongoose 8/9?"
A4: Modern Mongoose natively supports Promises. When an `async` function is passed 
    to `pre('save')`, Mongoose awaits the returned Promise and intentionally does 
    NOT pass a `next` callback. Calling `next()` attempts to invoke `undefined`. 
    The modern pattern is to omit `next` and return early or let the async resolve.

Q5: "What is a Mass Assignment vulnerability and how does Zod stop it?"
A5: Mass Assignment occurs when unvalidated user input (`req.body`) is passed 
    directly to `Model.create(req.body)`. An attacker can inject `{ role: 'admin' }` 
    to gain privileges. Chaining `.strict()` on Zod schemas causes the validator 
    to reject any unexpected property with an HTTP 400 at the API boundary.

Q6: "What is Token Rotation and why is it superior to static refresh tokens?"
A6: Static refresh tokens allow an attacker who steals a token to issue access 
    tokens indefinitely. With Token Rotation, using a refresh token immediately 
    invalidates it and replaces it with a new one in MongoDB. If a stolen, 
    previously used refresh token is presented, the server detects reuse and 
    revokes the entire session.

Q7: "Why is select: false used on passwords in Mongoose?"
A7: Defense in Depth. It guarantees that standard queries (`find`, `findOne`) 
    strip the password hash from the returned document, preventing accidental 
    leaks in API JSON responses or console logs. Queries must explicitly opt-in 
    using `.select('+password')`.

Q8: "What is the ESR rule in MongoDB indexing?"
A8: Equality, Sort, Range. In compound indexes, place fields matched with exact 
    equality first, fields used for sorting second, and fields with range operators 
    (`$gt`, `$lt`) last. This guarantees the B-tree resolves the query in RAM 
    without collection scans or in-memory sorts.

Q9: "What is POSIX SIGTERM and what happens during Graceful Shutdown?"
A9: SIGTERM (Signal 15) is the termination signal sent by Docker, Kubernetes, 
    or AWS ECS when replacing containers. Graceful shutdown stops accepting new 
    connections (`server.close()`), waits for in-flight HTTP requests to drain, 
    closes database connection pools, and exits cleanly with code 0.

Q10: "How does Zod protect against NoSQL Injection?"
A10: Attackers send objects with MongoDB operators like `{"email": {"$ne": null}}`. 
     Without validation, MongoDB matches the first user in the database. Zod's 
     `z.string().email()` enforces primitive strings and rejects objects with 400.
